# Design Item `7e3a91-0001` — `implementer-e2e.txt artifact contract`

## Purpose

This Design Item defines the exact path and byte content of the single artifact that the IMPLEMENTER must produce during the IMPLEMENTER delegation E2E test for Work `261010-implementer-e2e-7e3a91`.

## Scope
### In
- Fix the literal artifact path: `project-261010-implementer-e2e-7e3a91/implementer-e2e.txt`
- Fix the exact byte content: `implementer delegation test\n` (28 ASCII bytes including the single trailing LF)
- Fix the byte-level contract that the IMPLEMENTER must reproduce and the REVIEWER will byte-equal compare

### Out
- Implementation method (which editor or shell command is used)
- Any additional modules, test frameworks, fixtures, or harness code
- Any watcher / cron / kanban / webhook / adapter code
- Any HUMAN-only transitions (`work_state=CLOSED`, `closure_result=COMPLETE/INCOMPLETE`)

## Current Problem

The Hermes native delegation path (`monitor → Watcher → delegate_task → IMPLEMENTER child`) has been added a branch in `workspace-tas-watcher` Skill but has never been exercised against a real Work end to end. No Work exists yet whose `next_actor=IMPLEMENTER` is read by the Watcher, dispatched to a child, and successfully handed off to `next_actor=REVIEWER` afterwards.

## Required Outcome

After this Work's `next_actor=IMPLEMENTER` Watch tick, the IMPLEMENTER child must produce exactly one file at the path above with exactly the bytes above (28 bytes, single trailing LF, no CRLF, no UTF-8 BOM, no trailing whitespace), commit it on the `impl/261010-implementer-e2e-7e3a91` branch, push it to the remote, and update Work Canonical so `next_actor=REVIEWER` is recorded.

## Constraints

- The artifact path is fixed exactly: `project-261010-implementer-e2e-7e3a91/implementer-e2e.txt`. No prefix changes, no renaming, no extra subfolders.
- The artifact content is fixed exactly: the 28 ASCII bytes `implementer delegation test\n` (no CRLF, no BOM, no trailing whitespace).
- The IMPLEMENTER child must not be granted `write_file` or `patch` beyond the parent's toolset. It must produce the artifact using only `terminal` (writing to disk and using `git add` / `git commit` / `git push`).
- No new abstraction, common orchestration layer, Webhook, Kanban, or separate Workflow Engine is created for this test.
- `work_state=CLOSED`, `closure_result=COMPLETE/INCOMPLETE` are never recorded during this test — those are HUMAN-only transitions.

## Decision

The IMPLEMENTER will produce exactly one file. The contract is the path, the byte content, and the byte-level invariants above. Implementation method (which shell command, which editor, which sequence of git operations) is at IMPLEMENTER's discretion as long as the result is byte-equal and the Work Canonical Handoff records `next_actor=REVIEWER` afterwards.

## Interfaces / Data / State

- Artifact path: `project-261010-implementer-e2e-7e3a91/implementer-e2e.txt` on branch `impl/261010-implementer-e2e-7e3a91`
- Artifact content: 28 bytes — ASCII `implementer delegation test` followed by a single `\n`
- SHA-256 of expected blob (LF only, no CRLF): to be computed by the IMPLEMENTER and recorded in the Implementation Result for the Reviewer's byte-equal check
- Work Canonical state at the end of IMPLEMENTER Handoff:
  - `STATUS.yaml.next_actor = "REVIEWER"`
  - `STATUS.yaml.last_actor = "IMPLEMENTER"`
  - `STATUS.yaml.active_impl_commit = <the new impl branch commit SHA>`
  - `STATUS.yaml.based_on_work_commit = <the Work branch HEAD immediately before this Handoff>`

## Verification Criteria

- `git cat-file blob origin/impl/261010-implementer-e2e-7e3a91:project-261010-implementer-e2e-7e3a91/implementer-e2e.txt | sha256sum` returns the SHA-256 recorded by the IMPLEMENTER
- `wc -c` on the blob (via `git cat-file -s`) returns 28
- `git show origin/work/261010-implementer-e2e-7e3a91:work/261010-implementer-e2e-7e3a91/STATUS.yaml` shows `next_actor=REVIEWER`, `last_actor=IMPLEMENTER`, and the correct `active_impl_commit` / `based_on_work_commit`
- The Work's `work_state` remains `PROGRESS`; `closure_result` stays `null` — never `CLOSED`/`COMPLETE`/`INCOMPLETE` during this test
